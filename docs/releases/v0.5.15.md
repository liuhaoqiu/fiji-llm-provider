# Fiji LLM Provider 0.5.15 (local rollback)

**English** | [简体中文](v0.5.15.zh-CN.md)

Remove the background-run receipt parser introduced in 0.5.13. Restore StreamActivity source and class bytes exactly to 0.5.12: this monitor uses only tool start/finish metadata and API activity, and never inspects tool result contents. This is a rollback of that feature, not just a guard around its text conversion.

The optional tool-status/presentation callback is isolated from downstream tool delivery. Its RuntimeException, LinkageError or AssertionError is logged without changing the original tool result, preventing its delivery, or stopping the next model round. The actual tool/API callback remains outside this guard; genuine task errors are not converted to successes. Image/multipart-aware parsing is retained for existing stage presentation. JVM-fatal failures are not treated as recoverable display errors.

The old 0.5.14 JAR reproduces interruption when a display sink throws. Real AI-service fault injection confirms continued downstream delivery, unchanged model/memory results and one final response with all three injected failure types. Existing pure-image, image+text and multiple-text callback regressions also pass. All 24 local suites and six isolated GUI checks passed without hosted inference or user images.

Other 0.5.13 fixes (busy diagnostics, evidence coverage and separate editor windows) are retained. Four provider implementations, defaults, licenses and upstream JARs are unchanged. This candidate is local only.
