# Fiji LLM Provider 0.5.18

[English](v0.5.18.md) | **简体中文**

## 修复：最终核验条指向已保存脚本

此前，分析包导出后，继续创建或运行清理脚本，可能让最终报告的核验条改为显示辅助脚本。导出文件本身没有变化，但展示关联错误。

现在，最终核验条使用**最近一次成功导出分析包时保存的脚本证据**。例如先导出 `analysis.ijm`、再运行 `cleanup.groovy`，核验条仍指向已保存的 `analysis.ijm` 快照，明确标注“最近保存的脚本快照核验”。

- 后续编辑不会被误说成编辑器当前代码已经运行。
- 保存失败或无效回执不会替换已成功保存的快照；再次成功导出后，选用最新快照。
- 导出后即使重命名编辑器标签，核验条仍保留保存时的文件名。
- 没有成功导出时，保持原有的最近脚本展示行为。
- Groovy 等不在宏精确字节核验范围内的语言仍显示 `not_monitored`；这不表示运行失败，应以对应执行回执为准。

本次是小范围展示修复：相较 0.5.17，JAR 中只有 `StagePresentation.class` 与版本清单发生变化。不修改原版 Fiji Chat / Script Editor，不改变科学方法或模型指令，不加速模型推理。

## 保留的能力

继续支持 DeepSeek、硅基流动、火山引擎 Ark、NVIDIA，动态模型目录、原有加密密钥管理、**默认每条消息 1000 轮工具调用**、按模型设置上下文预算及自动整理/完整本地记录、正文进展 / 折叠日志 / 最终报告三部分展示、显式命令输入和分析包导出。已有保存设置优先。

## 安装或升级

1. 先安装 Fiji Chat，保存工作并关闭 Fiji。
2. 从本次 Release 下载 `fiji-llm-provider-0.5.18.jar`，可用 `SHA256SUMS.txt` 校验。
3. 将 JAR 放入 Fiji 的 `jars/`，停用旧的 provider 扩展，只保留一个活动版本。保留原版 Fiji Chat 和 Script Editor JAR。
4. 重启 Fiji。在 **Help → Assistants → Manage API Keys...** 管理密钥；通过 **Help → Assistants → Refresh LLM Models...** 刷新目录，完成后重新打开模型选择器。

源码 ZIP 用于查看或构建，安装不需要。模型必须支持工具调用才能执行代理任务，发送图像还要求视觉能力；出现在目录中不代表这些能力都受支持。

## 验证与边界

最终构建通过 **24 组本地回归**，安装目录复查覆盖服务/类来源、错误渲染、展示故障隔离、图像/多内容回调和聊天历史呈现。真实回执对照在未修改的 0.5.17 复现错误，在 0.5.18 通过。测试覆盖导出后清理、后续编辑、失败导出、多次导出、暂停、未覆盖语言及请求隔离。本次展示修复未重复原生 GUI 套件。

随后独立审阅了两次用户实际运行：细胞核任务交付 **267 标签 = 267 行 CSV = 267 个 ROI**；细胞/细胞核任务交付 **283/258 标签**，分别与 CSV 和 ROI 数量一致。文件哈希、源图像素、测量和导出 QC 已核验。后者也经历上下文整理并继续完成执行、导出和最终输出。这证明实际观察到的工程一致性，不证明生物学准确性或空白状态复现；模型仍出现过脚本/API 使用错误及报告算术错误。

两次完整任务耗时分别约 **7 分 15 秒**、**16 分 30 秒**；任务和模型决策不同，不构成控制变量速度对比，也不是 0.5.18 的加速承诺。

验证环境：Windows 11、Java 21.0.7、Fiji/ImageJ 2.18.0 / 1.54p、Fiji Chat `0.2.0-SNAPSHOT`（提交 `f73180448c64c83edeb995dd96156d1dd68f7896`）、LangChain4j 1.21.0、Script Editor 1.4.3。未来上游构建需要兼容性检查，服务商错误/超时仍可能发生。发布包不包含私有任务日志、图像或密钥。
