# Fiji LLM Provider 0.5.5

**English** | [简体中文](v0.5.5.zh-CN.md)

This release brings the long-task improvements developed in 0.5.2–0.5.5 to the
public release channel. It upgrades the independent provider extension; the Fiji
Chat core JAR is unchanged. DeepSeek, SiliconFlow, Volcengine Ark and NVIDIA remain
in one installable JAR, with a default of **1000 tool-calling rounds per message**.
An explicitly saved round limit is preserved.

## What changed since 0.5.1

- **Keep the task during long runs.** Restore the original request and recent
  follow-ups after image-heavy conversation memory evicts older messages, even
  when the next request is below its budget. Keep each chat's task separate and
  label tool-image messages as continuation evidence. This fixes cases where an
  assistant incorrectly claimed that the user's request was empty after compaction.
- **Manage context before requests become too large.** Configure automatic,
  512K or 1M windows with a separate output reserve. Monitor approximate input
  tokens, exact serialized UTF-8 request bytes and the last API-reported usage.
  Automatic compaction keeps bounded excerpts, the task and recent complete tool
  exchanges; full messages and received progress remain in a local archive.
- **Keep activity visible after compaction.** Preserve subsequent activity and
  final-answer delivery, with a visible phase checkpoint when context is organized.
- **Show honest waiting and recovery states.** After 60 seconds without new
  output/events, distinguish API waits from tool waits and show the last finished
  tool. These notices are plugin status, not model reasoning or proof of progress.
  Recognized context/transport interruptions and empty final replies produce a
  **Task paused — not completed** checkpoint for continuation in the same chat,
  without automatic request retries or tool replay.
- **Cover stalled streaming bodies.** The existing 30-minute response timeout now
  also covers idle SSE body reads after response headers. Keepalive comments do
  not reset it; active data events do. Long synchronous tool callbacks are allowed
  to finish. This is an inactivity safeguard, not a total task-duration limit.
- **Use SiliconFlow's official context metadata.** Supplement context lengths
  missing from its API catalog with the official public model page, without a
  hardcoded model-ID list. Cache metadata for 24 hours and retain valid cached
  values if refresh fails. Refresh LLM Models forces a metadata refresh too.
  Unknown models use a disclosed conservative fallback. No API key or conversation
  content is sent to the public model page.
- **Avoid premature byte-triggered compaction.** Move the request-body soft trigger
  to 90% while keeping the token trigger at 80%. Request bytes and token capacity
  remain separate limits; a large image can hit the byte budget first.

## Install or upgrade

1. Install [Fiji Chat](https://github.com/fiji/fiji-llm#fiji-chat-quick-start) first.
2. Save scripts, images, ROIs and results, then **close Fiji**.
3. Download `fiji-llm-provider-0.5.5.jar` and optionally verify it against
   `SHA256SUMS.txt`. Copy the JAR into your Fiji installation's **`jars`** directory.
4. Move older `fiji-llm-provider-*.jar` / `fiji-deepseek-provider-*.jar` files out
   of `jars`, or disable their `.jar` suffix. Keep only one active extension.
   Keep the original `fiji-llm-*.jar` installed.
5. Restart Fiji. Configure provider keys under **Help → Assistants → Manage API Keys...**.
6. Update model lists via **Help → Assistants → Refresh LLM Models...**, then
   reopen Fiji Chat's model chooser.

The source ZIP is for inspection/building; it is not needed for installation.

## Context settings and continuing a paused task

- **Help → Assistants → LLM Execution Settings...**: choose `0` for model metadata,
  `524288` for 512K or `1048576` for 1M. The default output reserve is 65,536 tokens,
  clamped to the selected model/window. Reopen Fiji Chat after changing settings.
- **Help → Assistants → LLM Context Status...**: inspect the active assistant's
  window, metadata source, token estimate, measured bytes, usage and waiting state.
  Before its first request, “No request yet” and zero values are normal.
- A verified SiliconFlow `deepseek-ai/DeepSeek-V4.1-Flash` entry has a 1,048,576-token
  total window and a 983,040-token input budget after the default output reserve.
  This does not establish a 1M window for other models or endpoints. **1M tokens
  is not 1 MiB.** The default local body cap is 48 MiB for official DeepSeek and
  a conservative 16 MiB for other providers; the latter is not a claimed server limit.
- If a checkpoint says the task paused, reply **continue** in the same chat and
  retain any remaining requirements. Save the editor/image state. Archives are
  local records, not automatic restoration of external tools or processes.
- Models must support tool calling for Fiji actions and image input for visual
  work. A catalog listing alone does not guarantee those capabilities.

## Verification and limits

**All 13 local verification suites passed**, including the real 1000/1001-round
boundary, image-driven memory eviction, independent chats, outgoing task
retention, post-compaction activity in the Fiji chat panel, empty replies,
idle SSE bodies/keepalives, delayed responses and Fiji history serialization.
The previous 0.5.4 task-loss defect was independently reproduced with the same
regression fixture. SiliconFlow's public 1M metadata was checked online.

Verified dependency set: Windows 11, Fiji/ImageJ 2.18.0 / 1.54p, Fiji Chat
0.2.0-SNAPSHOT, Java 21.0.7 and LangChain4j 1.21.0; compiled for Java 17.
The release harness uses local servers/synthetic tools and performs **no hosted
inference**. It does not certify a particular microscopy analysis or guarantee
compatibility with future Fiji Chat updates. Existing damaged history is not
automatically repaired; see [Troubleshooting](../TROUBLESHOOTING.md).
