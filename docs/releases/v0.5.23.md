# Fiji LLM Provider 0.5.23

**English** | [简体中文](v0.5.23.zh-CN.md)

This release contains the reviewed changes of local versions 0.5.20 to 0.5.22, which were not published separately, together with 0.5.23. Every change comes from a problem observed in a real Fiji Chat task; none of them adds an analysis method, a retry policy or a new budget.

## What the model sees

**DeepSeek images are sent at full detail.** Fiji Chat sends images with the SDK default `detail=low`, and DeepSeek documents that value as downscaling the image to 512×512 before inference. A 1551×1552 microscope frame was therefore inspected at one third of its resolution. For the DeepSeek service only, such images are now sent with `detail=high`. The request body has the same size either way, and DeepSeek charges at most 1024 tokens per image, which is the per-image allowance this extension already budgets, so compaction thresholds do not move. Image bytes, chat memory and the local archive are unchanged. SiliconFlow, Volcengine Ark and NVIDIA keep the previous behaviour.

## Macros that reproduce without a click

**Macro option keys.** `fiji_command_parameters` listed SciJava input names such as `return_ROIs`, `labelType`, `torchVersion` and `useGPU` and told the model to prefer them. ImageJ looks macro options up in lower case, so in `run("Command...", options)` an input written with capitals is not found: the command opens its dialog, the delivered macro needs a click on every run, and those values come from the dialog instead of from the macro. Each input now also carries `macro_key`, taken from ImageJ's own key rule, and the result states when a dialog opens.

**Saving a script file.** New tool `fiji_script_save_file` writes the exact bytes of one script tab, identified by `script_handle` and `expected_sha256`, to an absolute path in an existing folder and returns the path, size and SHA-256. An existing file is replaced only with `overwrite=true`; a stale hash writes nothing. The editor tab is not saved, renamed or bound to the file. Models previously copied the whole macro into a second script to write it to disk, or drove the editor's Save dialog.

**Script evidence follows the script.** Execution evidence was stored under the script's `editor:tab` position. After earlier tabs were closed, a delivered macro could be compared with the run of the script that previously held its position and be reported as `modified_since_last_run` although those bytes had just run. Evidence is now kept with the live editor tab. This removes a false "not verified"; it never produced a false "verified", because the byte hash was always compared as well.

**Run-status tools wait.** `fiji_macro_run_status`, `fiji_script_run_status` and `fiji_command_run_status` answered immediately, so a model waiting for a run asked many times, each a full model request. They now accept `wait_seconds` (0–30, default 20), wait while the run is still running, and answer at once on completion, error or a dialog. The run is never replayed or cancelled, and Stop ends the wait.

## Reports and the chat body

**Reports in Chinese and English.** The extension has users of both languages. Progress updates are requested in both (Chinese, then English), and the final report as two complete versions under `### 中文` and `### English`. Code blocks appear once, after both versions. The final report becomes about twice as long.

**No line for a script that was only created or edited.** "Script created / Script updated … not execution-verified" appeared about ten times per task and said nothing that the run results, the saved-file line and the final badge do not already say. A failed create or edit is still reported.

**The note in LLM Execution Settings wraps.** It was rendered as one line and made the dialog as wide as all of its sentences.

## Stopping and preprocessing

**Stop during reasoning.** Pressing Stop while the model was still reasoning cancelled the request but left this extension's wait monitor running. It kept recording "Waiting for new API output" once a minute until Fiji was closed. A stop now ends the request, the monitor and the assistant's cancelled state together.

**Commands on a preprocessed channel.** `fiji_command_run_with_inputs` refused an image from `fiji_image_extract_channel` once its pixels had been changed. That blocked ordinary preprocessing such as inverting before segmentation, and was bypassed by duplicating the image in a macro. The command now runs, and its receipt states `input_changed_since_extraction` with a note that the input was not raw source pixels. The analysis bundle is unchanged: it still refuses a modified channel as its source image, because the bundle records that image as unprocessed. Painted QC displays are still refused as command input.

## Scope

Compared with 0.5.19, these classes and the version manifest differ in the JAR: `AbstractCatalogProvider`, `CommandBridge`, `ConfigureAssistantExecution`, `DeepSeekProvider`, `ImageEvidence`, `ProgressAssistant`, `ProviderAssistantService`, `ScriptTargets`, `ScriptValidation`, `StagePresentation`, `StageReporting`, `UiAutomationTools` and `WorkflowTools`. The original Fiji Chat and Script Editor JARs are not modified.

The repository's text files were also normalised to the line endings declared in `.gitattributes`, in a separate commit that changes line endings only. A fresh clone no longer reports modified files.

## Install or upgrade

1. Install Fiji Chat first. Save your work and close Fiji.
2. Download **fiji-llm-provider-0.5.23.jar** from this release and optionally verify it with **SHA256SUMS.txt**.
3. Copy the JAR into Fiji's **jars/** directory. Disable older provider-extension JARs so only one extension version is active. Keep the original Fiji Chat and Script Editor JARs.
4. Restart Fiji. Manage keys through **Help → Assistants → Manage API Keys...**. Refresh models through **Help → Assistants → Refresh LLM Models...**, then reopen the model chooser.

The source ZIP is for inspection and building, not installation.

## Verification and limits

**All 26 regression suites pass in one build**, against the Fiji Chat build named below. New checks cover each change above: a stop during reasoning; DeepSeek image detail with unchanged memory, estimate and other providers; evidence that follows a script across tab positions; exact script file saving with no silent overwrite; macro keys resolved by ImageJ's own option parser for the real Cellpose-SAM command; bounded waits on run-status tools; both report languages in the presentation protocol; no body line for script edits; and commands that accept a preprocessed channel while the bundle still refuses it.

Four real tasks on the same image were run with DeepSeek during development. They exercised the full-detail images, bilingual reports, macro keys without a dialog, script file saving and the shorter chat body.

Not verified:

- The bounded wait was tested with simulated status tools, not against Fiji Chat's real ones; in the last real task no status query was needed.
- The preprocessed-channel path was not taken in a real task.
- The native GUI suites (`-VerifyMacroIntegration`) were not run for this release.
- `detail=high` is checked in the request the extension hands to the SDK, not in a network capture, and not with an online comparison.
- No check here says anything about scientific accuracy. In the four real tasks the model chose different methods and reported 3022, 3012, 5230 and 3697 cells for the same image.

Tested environment: Windows 11, Java 21.0.7, Fiji/ImageJ 2.18.0 / 1.54p, Fiji Chat 0.2.0-SNAPSHOT commit 1dea483ee7285efb86689902b4cae56dcd66a549, LangChain4j 1.21.0, Script Editor 1.4.3. Future upstream builds require compatibility checks. Private logs, images, credentials and dependency JARs are not bundled.
