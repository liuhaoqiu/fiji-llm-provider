# Fiji LLM Provider 0.5.5

[English](v0.5.5.md) | **简体中文**

本次将 0.5.2–0.5.5 的长任务改进汇总发布。更新的是独立扩展插件，**没有修改 Fiji Chat
本体 JAR**。DeepSeek、硅基流动、火山引擎 Ark 和 NVIDIA 仍由一个 JAR 提供支持，
默认 **每条用户消息 1000 轮工具调用**；升级保留已保存的自定义上限。

## 相比 0.5.1 的主要变化

- **长任务保留原始目标。** 图像消息挤出旧记忆后，重新加入原始请求及近期补充要求，
  即使下一次请求尚未超出预算也会检查；不同聊天独立保存任务。工具图像明确标为
  继续执行的证据，修复整理上下文后误称“用户消息为空”、遗忘任务的问题。
- **发送前管理上下文。** 支持自动、512K、1M 窗口及独立的输出预留。
  监测估算输入 token、实际 UTF-8 请求字节和最近一次 API 返回的用量。
  自动整理保留有限摘录、任务及近期完整工具交互；完整消息和已接收的进度保存在本地归档。
- **整理后继续显示运行活动。** 保留后续活动及最终答复，并在整理时显示阶段检查点。
- **明确等待和暂停状态。** 60 秒没有新输出或事件后，区分等待 API 与等待工具，显示最近完成的工具。
  这是插件状态，不代表模型推理或已确认的任务进展。可识别的上下文/连接中断及空最终回复
  会保留 **Task paused — not completed（任务暂停，尚未完成）** 检查点，支持同一聊天继续，
  不会自动重试请求或重放工具。
- **处理流式响应停滞。** 现有 30 分钟响应超时也覆盖收到响应头后停滞的 SSE 正文；
  keepalive 注释不算模型输出，实际数据事件会刷新计时，耗时的同步工具回调可正常结束。
  这是无活动超时，不是整个任务的总时长限制。
- **采用硅基流动官方窗口元数据。** 从官方公开模型页补全 API 目录缺少的窗口长度，
  不写死模型 ID 列表。缓存 24 小时，刷新失败保留有效缓存；刷新模型菜单也会强制刷新元数据。
  未知模型采用并显示保守回退值。不会向公开模型页发送 API 密钥或聊天内容。
- **减少过早整理。** 请求字节的软触发阈值调整到 90%，token 触发阈值保持 80%。
  token 容量与请求字节限制分别管理，大图仍可能先触及字节预算。

## 安装或升级

1. 先安装 [Fiji Chat](https://github.com/fiji/fiji-llm#fiji-chat-quick-start)。
2. 保存脚本、图像、ROI 和结果，**正常关闭 Fiji**。
3. 下载 `fiji-llm-provider-0.5.5.jar`，可对照 `SHA256SUMS.txt` 核验；
   将 JAR 放入 Fiji 安装目录的 **`jars`** 文件夹。
4. 移走旧的 `fiji-llm-provider-*.jar` / `fiji-deepseek-provider-*.jar`，
   或修改其 `.jar` 后缀，只保留一个启用版本。保留原版 `fiji-llm-*.jar`。
5. 重启 Fiji，在 **Help → Assistants → Manage API Keys...** 设置服务商密钥。
6. 在 **Help → Assistants → Refresh LLM Models...** 更新模型，完成后重新打开模型选择器。

普通安装不需要源码 ZIP。完整指南：[English](../../README.md) | [简体中文](../../README.zh-CN.md)。

## 上下文设置与暂停后继续

- **Help → Assistants → LLM Execution Settings...**：`0` 使用模型元数据，
  `524288` 为 512K，`1048576` 为 1M。默认输出预留 65,536 token，并按模型/窗口收缩。
  修改后重新打开 Fiji Chat。
- **Help → Assistants → LLM Context Status...**：查看当前助手窗口、元数据来源、token 估算、
  实际字节、用量和等待状态。首次请求前显示 “No request yet” 和零值属正常初始状态。
- 已在线核验的硅基流动 `deepseek-ai/DeepSeek-V4.1-Flash` 总窗口为 1,048,576 token，
  默认预留输出后输入预算为 983,040 token。这不代表其他模型或接入点都支持 1M。
  **1M token 不等于 1 MiB**。官方 DeepSeek 默认请求体上限为 48 MiB；
  其他服务商默认采用本地保守值 16 MiB，该值不是对服务端限制的声明。
- 出现暂停检查点后，在同一聊天中回复“继续”，保留剩余要求，并保存编辑器和图像状态。
  本地归档是记录，不会自动恢复外部工具或进程。
- Fiji 操作需要工具调用能力，视觉任务还需要图像输入能力；列入模型目录不代表支持这些能力。

## 验证范围与限制

**十三组本地验证全部通过**，覆盖真实 1000/1001 轮边界、图像引起的记忆淘汰、不同聊天隔离、
发送请求中的任务保留、Fiji 聊天面板整理后的活动显示、空回复、停滞 SSE/keepalive、
延迟响应和 Fiji 历史序列化。同一回归用例独立复现了旧版 0.5.4 的任务丢失问题，
并在线核验了硅基流动公开的 1M 元数据。

已验证环境：Windows 11、Fiji/ImageJ 2.18.0 / 1.54p、Fiji Chat 0.2.0-SNAPSHOT、
Java 21.0.7、LangChain4j 1.21.0；按 Java 17 编译。
发布测试使用本地服务器及合成工具，**没有调用托管模型推理 API**，不代表具体显微图像分析
已获科学验证，也不保证兼容所有未来 Fiji Chat 更新。既有损坏历史不会自动修复，
详见[故障排查](../zh-CN/TROUBLESHOOTING.md)。
