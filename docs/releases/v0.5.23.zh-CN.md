# Fiji LLM Provider 0.5.23

[English](v0.5.23.md) | **简体中文**

本版包含本地版本 0.5.20 至 0.5.22 经审阅的修改（这三个版本没有单独公开发布）以及 0.5.23 的修改。每一项都来自真实 Fiji Chat 任务中观察到的问题；没有增加分析方法、重试策略或新的预算。

## 模型看到的图像

**DeepSeek 图像按原图细节发送。** Fiji Chat 发送图像时使用 SDK 默认的 `detail=low`，DeepSeek 文档说明该取值会在推理前把图像缩到 512×512。一张 1551×1552 的显微图像因此只以三分之一的分辨率被查看。现在仅对 DeepSeek 服务把这类图像改为 `detail=high` 发送。两种取值的请求体大小相同；DeepSeek 每张图最多计 1024 token，正是本扩展原本为每张图预留的数值，所以整理阈值不变。图像字节、聊天记忆和本地归档不变。硅基流动、火山引擎 Ark 和 NVIDIA 保持原行为。

## 不用点击就能复现的宏

**宏参数键名。** `fiji_command_parameters` 列出的是 SciJava 输入名，如 `return_ROIs`、`labelType`、`torchVersion`、`useGPU`，并提示模型优先使用它们。而 ImageJ 是按小写查找宏参数的，所以在 `run("Command...", options)` 里带大写写出的输入找不到：命令会弹出对话框，交付的宏每次运行都要点一次，并且这些参数实际取自对话框而不是宏。现在每个输入同时给出按 ImageJ 自身规则得到的 `macro_key`，结果里也写明什么情况下会弹对话框。

**保存脚本文件。** 新增工具 `fiji_script_save_file`：按 `script_handle` 和 `expected_sha256` 把一个脚本标签的精确字节写到已存在文件夹中的绝对路径，返回路径、大小和 SHA-256。已有文件只有在 `overwrite=true` 时才被替换；哈希过期则什么都不写。编辑器标签不会被保存、重命名或绑定到该文件。此前模型只能把整份宏再抄进另一个脚本来写盘，或去操作编辑器的保存对话框。

**脚本核验跟随脚本本身。** 执行核验记录此前按脚本的 `editor:tab` 位置保存。关闭前面的标签后，已交付的宏可能被拿去和原先占据该位置的另一个脚本的运行记录比较，被报告为 `modified_since_last_run`，尽管这些字节刚刚运行过。现在记录与编辑器中的标签对象绑定。这消除的是误报“未核验”；因为始终还要比较字节哈希，此前也不会误报“已核验”。

**运行状态工具支持等待。** `fiji_macro_run_status`、`fiji_script_run_status`、`fiji_command_run_status` 此前立即返回，模型等待一次运行要查询很多次，每次都是一轮完整的模型请求。现在它们接受 `wait_seconds`（0–30，默认 20），在运行未结束时等待，完成、出错或出现对话框时立即返回。不会重放或取消运行本身，点击停止会结束等待。

## 报告与聊天正文

**中英双语报告。** 扩展的用户既有中文用户也有英文用户。现在要求进度更新用两种语言书写（先中文后英文），最终报告写成 `### 中文` 和 `### English` 两份完整版本。代码块只出现一次，放在两份之后。最终报告长度约为原来的两倍。

**脚本仅被创建或编辑时不再显示提示行。** “脚本已创建 / 脚本已更新……尚未运行验证”每次任务会出现十来次，而其内容在执行结果行、脚本文件保存行和最终核验条里都已包含。创建或编辑失败仍会提示。

**LLM Execution Settings 窗口的说明文字自动换行。** 此前它被渲染成一行，把窗口撑到与全部句子等宽。

## 停止与预处理

**思考阶段的停止。** 模型仍在“思考”时点击停止，请求会被取消，但本扩展的等待状态监视器没有随之结束，会每分钟继续记录“等待 API 新输出”，直到关闭 Fiji。现在停止会同时结束请求、监视器并标记该助手已取消。

**在预处理过的通道上运行命令。** `fiji_command_run_with_inputs` 此前会拒绝像素已被修改的 `fiji_image_extract_channel` 图像。这挡住了“先反相再分割”一类常规预处理，而且在宏里复制图像即可绕过。现在命令会正常运行，回执中给出 `input_changed_since_extraction`，并说明输入不是原始像素。分析交付包不变：仍拒绝把被修改的通道作为原图保存，因为交付包把该图记录为未处理的原始图像。带绘制内容的 QC 显示图仍不能作为命令输入。

## 改动范围

与 0.5.19 相比，JAR 中这些类和版本清单不同：`AbstractCatalogProvider`、`CommandBridge`、`ConfigureAssistantExecution`、`DeepSeekProvider`、`ImageEvidence`、`ProgressAssistant`、`ProviderAssistantService`、`ScriptTargets`、`ScriptValidation`、`StagePresentation`、`StageReporting`、`UiAutomationTools`、`WorkflowTools`。原版 Fiji Chat 和 Script Editor 的 JAR 没有修改。

仓库中的文本文件也按 `.gitattributes` 声明的换行符做了规范化，放在一个只改换行符的独立提交里。全新克隆不再显示有文件被修改。

## 安装或升级

1. 先安装 Fiji Chat，保存工作并关闭 Fiji。
2. 下载本页 **fiji-llm-provider-0.5.23.jar**，可用 **SHA256SUMS.txt** 核对。
3. 放入 Fiji 的 **jars/**，停用旧的 provider 扩展，只保留一个活动版本。保留原版 Fiji Chat / Script Editor JAR。
4. 重启 Fiji。密钥通过 **Help → Assistants → Manage API Keys...** 配置；刷新模型通过 **Help → Assistants → Refresh LLM Models...**，完成后重新打开模型选择器。

源码 ZIP 用于查看或构建，安装不需要。

## 验证与边界

**26 组回归在一次构建中全部通过**，对应下面列出的 Fiji Chat 构建。新增的检查覆盖上述每一项：思考阶段的停止；DeepSeek 图像细节及其对记忆、估算和其他服务商无影响；核验记录在标签位置变化后仍跟随脚本；脚本文件的精确保存与不静默覆盖；用 ImageJ 自身的参数解析器验证真实 Cellpose-SAM 命令的宏键名；运行状态工具的有界等待；汇报协议中的两种报告语言；脚本编辑不产生正文行；命令接受预处理过的通道而交付包仍然拒绝。

开发期间用 DeepSeek 在同一张图像上运行了四次真实任务，实际用到了原图细节的图像、双语报告、不弹对话框的宏键名、脚本文件保存和更简洁的聊天正文。

未验证的部分：

- 有界等待只用模拟的状态工具测试过，没有对接 Fiji Chat 本体真实的状态工具；最后一次真实任务中没有发生状态查询。
- 预处理通道这条路径在真实任务中没有被走到。
- 本版没有运行原生 GUI 套件（`-VerifyMacroIntegration`）。
- `detail=high` 是在扩展交给 SDK 的请求里核对的，没有抓取网络数据包，也没有做在线对比。
- 这些检查都不说明科学准确性。四次真实任务中模型选择了不同的方法，对同一张图像报告的细胞数分别是 3022、3012、5230 和 3697。

环境：Windows 11、Java 21.0.7、Fiji/ImageJ 2.18.0 / 1.54p、Fiji Chat 0.2.0-SNAPSHOT（提交 1dea483ee7285efb86689902b4cae56dcd66a549）、LangChain4j 1.21.0、Script Editor 1.4.3。未来上游构建仍需兼容性检查。不包含私有日志、图像、密钥或依赖 JAR。
