# Fiji LLM Provider 0.5.8

[English](v0.5.8.md) | **简体中文**

本次将 0.5.6–0.5.8 的改进发布到 GitHub。一个扩展 JAR 继续支持 DeepSeek、
SiliconFlow、Volcengine Ark 和 NVIDIA，默认每条用户消息 **1000 轮工具调用**，
保留已保存的自定义上限。Fiji Chat 与 Script Editor 本体保持原样。

## 主要变化

- **正文阶段进展**：公开中间回复和新增的助手内 `fiji_report_progress` 工具可在执行中汇报关键进展。
  支持的脚本修改、执行状态变化也会显示，重复运行状态查询会去重。
- **折叠运行日志**：推理、工具参数和原始返回值保留在原日志区域；上下文整理的内部摘录留在
  日志/本地记录中，正文只显示简短的继续执行提示。
- **独立最终报告**：最后一轮回答在独立标题下显示，前面的阶段进展继续保留。
  中断时保留并标记未完成正文；会话保存重载后仍能显示正文与日志。
- **宏执行兼容**：区分宏求值与编辑器/控制台维护线程，识别空闲公共线程池及 ImageJ 层选择器，
  增加剩余子线程诊断，保留运行 ID、对话框/错误状态、等待上限及连续宏执行。
- 保留 0.5.5 的上下文监测、原始任务保留、自动整理和可继续的中断检查点。

## 安装或升级

1. 先安装 [Fiji Chat](https://github.com/fiji/fiji-llm)。
2. 保存宏/脚本、图像、ROI 和结果表，然后**正常关闭 Fiji**。
3. 下载 `fiji-llm-provider-0.5.8.jar`，放入 Fiji 的 `jars` 目录。
4. 停用/移走旧的 provider 扩展 JAR，只保留一个生效版本；保留原版 `fiji-llm-*.jar`
   和 Script Editor JAR。
5. 重启 Fiji，重新打开 Fiji Chat 并发送新请求。四个新增服务商默认启用新的展示方式。

密钥管理路径：**Help → Assistants → Manage API Keys...**。
模型刷新路径：**Help → Assistants → Refresh LLM Models...**，完成后重新打开模型选择器。
执行/上下文设置仍在 **Help → Assistants → LLM Execution Settings...**。
已结束的历史会话保留原有显示，不追溯改写。

## 验证

**十六组本地测试全部通过**，包含真实 AI 服务的汇报工具循环、已安装聊天面板、历史重载、
取消回调、整理后的活动显示、四个服务商及真实 1000/1001 轮边界。另通过真实编辑器/模块 GUI 验证。
0.5.8 中宏执行类的字节与已验证的 0.5.7 JAR 一致，此前的大图 Cellpose 回归另有记录。
本次发行测试未使用托管推理或私人图像，详见[验证说明](../zh-CN/VERIFICATION.md)。

已验证环境：Windows 11；Fiji/ImageJ 2.18.0 / 1.54p；Fiji Chat 0.2.0-SNAPSHOT；
Script Editor 1.4.3；Java 21.0.7；LangChain4j 1.21.0；编译目标 Java 17。
本地测试不等同于真实托管模型对新工具的采用情况，也不保证未来依赖组合兼容。

## 已知限制

- 后续真实任务暴露了普通 `ThreadPoolExecutor` 工作线程在 `getTask()` 待命时，宏完成判定仍可能
  继续等待的问题。**0.5.8 尚未修复这一路径**；新增诊断有助于识别。宏主体已结束却仍阻塞时，
  先保存结果，再按需要重启 Fiji。
- 原有 UI 工具根据标题/类定位对话框；多个同名保存提示可能无法区分，需要手动处理。
  重复关闭同一窗口可能叠加提示框。
- 数值控件的提交及 Cellpose-SAM 宏参数映射还需要验证。本版不保证所有第三方插件均能无人值守，
  也不验证模型的科学结论。

这些剩余自动化问题将在下一版本地升级中处理。插件不强制结束线程，也不静默丢弃用户工作。
