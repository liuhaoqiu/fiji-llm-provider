# Fiji LLM Provider 0.5.17

**English** | [简体中文](v0.5.17.zh-CN.md)

This release consolidates the reviewed local changes from 0.5.13–0.5.17 since the last public release, 0.5.12. Fiji LLM Provider adds DeepSeek, SiliconFlow, Volcengine Ark and NVIDIA and improves Fiji Chat's execution feedback, progress display and long-task experience through one extension JAR.

## What changed since 0.5.12

- **Clear error dialogs:** progress distinguishes a normal input dialog from an explicitly reported macro error dialog, names the script and shows a bounded reason. Angle-bracket identifiers such as `<analysisId>` remain visible as literal code. Repeated status queries do not repeat the same milestone.
- **Display failures isolated from tool delivery:** optional presentation failures cannot swallow tool results or interrupt subsequent model rounds. Actual task/API errors still propagate. Image-only, image+text and multipart tool results retain their original payloads. The experimental background receipt parser from the local development versions was removed; activity monitoring uses start/finish metadata and API events.
- **More useful execution diagnostics:** busy starts identify the occupying script/run when known; startup failure causes remain available. Ordinary scripts handled by the upstream service are explicitly marked outside the macro version checker's coverage, rather than presented as never executed.
- **Editor compatibility:** when the latest Script Editor has active tasks, creating another script uses a separate editor window. This avoids the reproduced plugin-created-tab trigger for Script Editor 1.4.3's `Writer is null` error while retaining the upstream execution service.

## Observed task-time improvement

In repeated local tests of the same red-channel nuclei-counting request and 3000×3000 image, recent completed workflows took approximately **5–9 minutes**, compared with approximately **11 minutes 37 seconds** in the reviewed 0.5.12 run. The best recent observed run completed in about **5 minutes 5 seconds**.

| Local test version | First streamed event to final displayed report | Tool calls | Save-confirmation milestone |
| --- | --- | --- | --- |
| 0.5.12 | 11 min 37 s | 137 | +558 s |
| 0.5.15 | 6 min 37 s | 89 | +384 s |
| 0.5.16 | 5 min 5 s | 85 | +286 s |
| 0.5.17 | 9 min 4 s | 112 | +521 s |

These are observed end-to-end runs, not a controlled benchmark or a promised speedup. Model/provider latency, parameter exploration, repeated runs and workspace state varied. The 0.5.17 diagnostic-formatting fix itself does not accelerate inference or segmentation. The extension's cumulative completion/waiting and interaction improvements support a smoother workflow; individual task time still varies. Counts of tool calls are not counts of tool-calling rounds.

The reviewed 0.5.17 delivery contained 268 unique labels, 268 measurement rows and 268 matching ROIs. File hashes, exported source pixels, measurements and exported QC were independently checked. This validates engineering delivery consistency, not biological segmentation accuracy. The run also exercised the literal error-marker fix and automatic error-dialog handling.

## Capabilities retained

Four providers, dynamic model lists, the existing API-key vault, **1000 tool-calling rounds per message by default**, model-aware context budgeting and local archives, automatic compaction/recovery, public progress + folded activity + final report, initialized command inputs, stable script targets and exact-script snapshots, and explicit local analysis bundles are retained. Analysis methods and parameter choices remain the model's responsibility. Existing saved settings take precedence.

## Install or upgrade

1. Install Fiji Chat first. Save your work and close Fiji.
2. Download `fiji-llm-provider-0.5.17.jar` and optionally verify `SHA256SUMS.txt`.
3. Put the JAR in Fiji's `jars/` directory. Move or disable older provider extension JARs; keep one active extension. Keep the original `fiji-llm-*.jar` and Script Editor JARs.
4. Restart Fiji. Manage keys through **Help → Assistants → Manage API Keys...**. Refresh catalogs through **Help → Assistants → Refresh LLM Models...**, then reopen the model chooser.

The source ZIP is for inspection/building, not required for installation. A compatible model/endpoint must support tool calling; image input additionally requires vision support. Not all catalog models provide both. Saved analysis bundles require an explicit export-tool call; the resulting directory is reported in progress.

## Validation and scope

**24 local regression suites passed** for the final 0.5.17 build. The unchanged 0.5.16 build fails the new literal-rendering regression, and 0.5.17 passes using Fiji Chat's actual renderer. Installed-JAR probes verify service/class origin, rendering, image/multipart callbacks, injected display-failure isolation and chat/history presentation. The earlier 0.5.15 baseline passed six isolated native GUI integrations; these were not rerun for the one-line 0.5.17 presentation change. Unit/integration suites use synthetic tools/images and local servers; the real user-run checks above are separate observations.

Verified environment: Windows 11, Java 21.0.7, Fiji/ImageJ 2.18.0 / 1.54p, Fiji Chat `0.2.0-SNAPSHOT` at commit `f73180448c64c83edeb995dd96156d1dd68f7896`, LangChain4j 1.21.0 and Script Editor 1.4.3. The original Fiji Chat and Script Editor JARs are unmodified. This covers the tested binaries, not every future upstream snapshot. Provider-side errors/timeouts can still occur; execution evidence does not certify clean-state replay or scientific accuracy.

Original contributions remain **PolyForm Noncommercial 1.0.0**, with upstream BSD notices retained. No API keys or private task archives are included; the reviewed task images remain local.
