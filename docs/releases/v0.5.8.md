# Fiji LLM Provider 0.5.8

**English** | [简体中文](v0.5.8.zh-CN.md)

This release brings the 0.5.6–0.5.8 improvements to the public release channel.
DeepSeek, SiliconFlow, Volcengine Ark and NVIDIA remain in one extension JAR.
The default is **1000 tool-calling rounds per user message**; saved custom limits
are preserved. The Fiji Chat and Script Editor core JARs are unchanged.

## Highlights

- **Progress in the chat body:** public intermediate replies and the new
  assistant-local `fiji_report_progress` tool publish milestones while work
  continues. Supported script edits and execution-state changes also appear;
  duplicate running polls are suppressed.
- **Collapsible activity log:** thinking, tool arguments and raw results remain
  in Fiji Chat's existing activity area. Context-compaction internals stay in
  the log/local record while the body receives a short continuation notice.
- **Separate final report:** the last model reply appears once under its own
  heading, following the preserved progress. Interrupted public drafts are
  retained in a clearly labeled paused section. Saved display text and activity
  survive conversation-history serialization.
- **Macro execution compatibility:** isolate actual macro evaluation from
  editor/console maintenance, recognize idle common-pool workers and ImageJ
  stack-window selectors, and expose remaining child-thread diagnostics.
  Keep run IDs, dialog/error states, bounded waits and subsequent macro runs.
- Preserve the context monitoring, task retention, automatic compaction and
  recoverable interruption behavior from 0.5.5.

## Install or upgrade

1. Install [Fiji Chat](https://github.com/fiji/fiji-llm) first.
2. Save macros/scripts, images, ROIs and results, then **close Fiji**.
3. Download `fiji-llm-provider-0.5.8.jar` and copy it into Fiji's `jars` directory.
4. Disable/remove older provider-extension JARs so only one version is active.
   Keep the original `fiji-llm-*.jar` and Script Editor JAR installed.
5. Restart Fiji, reopen Fiji Chat and send a new request. The new display is
   enabled automatically for the four added providers.

Manage keys under **Help → Assistants → Manage API Keys...**. Refresh models
under **Help → Assistants → Refresh LLM Models...**, then reopen the model
chooser. Execution/context settings remain under **Help → Assistants → LLM
Execution Settings...**. Existing completed conversations retain their saved
display; they are not retroactively reformatted.

## Verification

All **16 local suites** passed, including real AI-service reporting-tool rounds,
the installed chat panel, saved-history replay, cancellation handles,
post-compaction activity, four providers and actual 1000/1001-round boundaries.
Additional real editor/module GUI checks passed. The macro execution classes in
0.5.8 are byte-identical to the verified 0.5.7 JAR; the earlier large-RGB Cellpose
regression is documented separately. No hosted inference or private image was
used in the 0.5.8 release tests. See [verification](v0.5.8-verification.md).

Verified environment: Windows 11; Fiji/ImageJ 2.18.0 / 1.54p; Fiji Chat
0.2.0-SNAPSHOT; Script Editor 1.4.3; Java 21.0.7; LangChain4j 1.21.0.
Compiled for Java 17. Hosted-model adoption of the reporting tool and future
dependency compatibility are not certified by the local tests.

## Known limitations

- A subsequent real workflow exposed a remaining completion wait involving
  ordinary `ThreadPoolExecutor` workers idle in `getTask()`. This is not fixed
  in 0.5.8; the new child-thread diagnostic helps distinguish it. Save results
  before restarting Fiji if the run remains blocked after its body has finished.
- Existing UI tools identify dialogs by title/class. Multiple same-title save
  prompts can be ambiguous and may require manual dismissal. Repeated close
  requests can worsen that ambiguity.
- Numeric widget commits and Cellpose-SAM macro-parameter mapping need further
  verification. This release does not guarantee fully unattended execution of
  every third-party plugin or validate the model's scientific conclusions.

These remaining automation issues are being addressed in the next local version.
The extension does not forcibly terminate threads or silently discard user work.
