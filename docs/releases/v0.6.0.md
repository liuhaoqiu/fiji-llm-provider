# Fiji LLM Provider 0.6.0

**English** | [简体中文](v0.6.0.zh-CN.md)

This release gives every chat one output folder and removes two sources of silent trouble that real tasks exposed: a macro option that switched the GPU off without a message, and tool results so large that they travelled with every later request. As before, each change comes from a problem observed in a real Fiji Chat task, and none of them adds an analysis method.

## One output folder per chat

Until now every chat decided for itself where its files went and what they were called. A chat that produces files now gets one folder of its own next to the input image:

```text
Fiji_chat_output_<yyyymmdd>_<n>/
  report.md          the final report as shown in the chat (a later answer: report_2.md)
  results/           the standard result set of a 2D label analysis (a second set: results_2/)
  scripts/           the script saved with fiji_script_save_file
  script_output/     where the chat's own scripts are asked to write
  process/           every script the chat ran, numbered in run order, and steps.md
  manifest.json      every file with size and hash, the input image, the assistant
```

The number counts the day's folders in that place. It is assigned by the extension, by creating the folder, so two chats can never share one and an existing folder is never reused. The new tool `fiji_output_folder` returns the folder; `fiji_script_save_file` and `fiji_analysis_save_bundle` use it by default.

**The standard result set** holds the label TIFF, a measurement table with fixed columns, one ROI per label, a QC image and the script snapshot. A source image that is an unchanged file on disk is named by path and pixel hash instead of being copied; any other source, such as a grey copy that exists only in memory, is saved with the set as `source.tif`. The fixed format covers 2D label analyses; other tasks get the folder, report, scripts, process records and manifest, with result files named by the model.

**Macros are not constrained.** A script may write wherever it is told, and a delivered macro often writes into a folder of its own next to the image. The manifest lists such files (up to three folders deep) under `new_files_next_to_the_input`. If a saved script contains this chat's folder as a literal path, the save result and the manifest say so, because such a script would write into the old folder when reused.

**Delivered macros stay independent of this extension.** The workflow guidance used to steer models towards `fiji_command_macro_template`, whose macro calls this extension and does not run in a Fiji without it. Models are now asked to write ordinary macro code. The tool remains for those who ask for it, and its description says what its macro depends on.

**What does not happen.** No folder for a chat that runs no script and saves nothing. No folder when the image was never saved to disk or its folder is not writable; records then stay in the local archive. Nothing the extension writes replaces an existing file. A failed write of a report, step or manifest never affects the analysis. The feature can be switched off in **LLM Execution Settings**.

## Boolean macro options written as 1

A macro variable set to `true` prints as `1`, and SciJava reads the option text `1` as false without any message. `run("Cellpose...", "... usegpu=" + useGPU)` therefore runs on the CPU. This happened in two real tasks; in one of them nobody noticed, and its summary stated that the GPU was on.

- `fiji_command_parameters` now states that a Boolean option must be the text `true` or `false`.
- When a macro started by a chat calls a command with a Boolean option that is neither, the result of `fiji_macro_run` or `fiji_macro_run_status` carries `macro_option_warnings` naming the command and the option, and the chat shows the line.

The second point is an observation only. It is a SciJava preprocessor that reads the option text where ImageJ's own macro preprocessor reads it. It changes no input and no result, and a macro behaves exactly as it would without this extension, inside a chat or outside one.

## Smaller tool results

**Long lists in very large tool results.** Tools that list every ROI or every table row return hundreds of thousands of characters for a few thousand objects, and the chat memory sends them again with every later request. In one real task two ROI listings of 520,000 and 550,000 characters travelled with more than a hundred requests. A tool result above 30,000 characters now has its longest JSON lists cut to their first 20 rows before the request is sent, until it fits. Each cut list ends with the number of rows omitted and the total; the result says that it was shortened and where the full one is; every other field is unchanged. Text is never cut, so scripts and logs arrive whole, and results below the limit are not touched. The full result stays in the local archive and the step log notes each shortening. It can be switched off in **LLM Execution Settings**.

**Result of `fiji_analysis_save_bundle`.** It used to repeat the label-to-ROI list, about 190,000 characters for 4,300 cells. A list of more than 20 rows is now named with an example row and the row count; the full list stays in the set's `manifest.json`.

## Scope

Compared with 0.5.23, these classes, the SciJava plugin index and the version manifest differ in the JAR: `AnalysisBundle`, `AssistantExecutionSettings`, `BoundedContext`, `ConfigureAssistantExecution`, `ProgressAssistant`, `ProviderAssistantService`, `StagePresentation`, `StageReporting`, `UiAutomationTools` and `WorkflowTools`, and the new `ChatOutput`, `LongLists` and `MacroOptionCheck`. The original Fiji Chat and Script Editor JARs are not modified.

## Install or upgrade

1. Install Fiji Chat first. Save your work and close Fiji.
2. Download **fiji-llm-provider-0.6.0.jar** from this release and optionally verify it with **SHA256SUMS.txt**.
3. Copy the JAR into Fiji's **jars/** directory. Disable older provider-extension JARs so only one extension version is active. Keep the original Fiji Chat and Script Editor JARs.
4. Restart Fiji. Manage keys through **Help → Assistants → Manage API Keys...**. Refresh models through **Help → Assistants → Refresh LLM Models...**, then reopen the model chooser.

The source ZIP is for inspection and building, not installation.

## Verification and limits

**All 27 regression suites pass in one build**, against the Fiji Chat build named below; the new suite covers the output folder. New checks cover each change above: folder numbering claimed by creating the folder; reports, scripts, steps and manifest written without replacing anything; standard results that copy the source only when it is not a file; files in folders a script created next to the input; the literal-folder warning; a switched-off feature, an unsaved image, an unwritable folder and failed writes that leave the analysis untouched; the Boolean option note and its silence for correct options; long lists cut with counts while text, short results and a switched-off setting leave results whole.

The six native GUI suites were run on the release build, together with two real calls of the installed Cellpose command from a macro: one with `usegpu=1`, which ran unchanged and was reported, and one with `usegpu=true`.

Five real tasks on one image were run with DeepSeek on builds of this version. They exercised the output folder, the report and step log, the manifest including files a macro left next to the image, the standard result set with and without a source copy, the smaller bundle result, and the bounded status wait on runs of up to six minutes.

Not verified:

- List shortening did not occur in a real task after it was added; it was tested with three archived results of real tasks (552,848, 519,790 and 59,247 characters) and with an archived 22,098-character list of interface controls, which is sent whole.
- The Boolean option warning did not occur in a real task, because the models wrote the option correctly once the parameter tool said how.
- The two new check boxes in **LLM Execution Settings** were not inspected on screen, and the screenshot in the README shows the dialog before this release.
- A GPU was requested in the real tasks; the Cellpose command does not report the device it used.
- No check here says anything about scientific accuracy. In the five real tasks the model reported 4304, 4306, 4296, 4296 and 4306 cells for the same image, and in each of them dense clumps of cells remained partly unsegmented.

Tested environment: Windows 11, Java 21.0.13.1, Fiji/ImageJ 2.18.0 / 1.54p, Fiji Chat 0.2.0-SNAPSHOT commit 1dea483ee7285efb86689902b4cae56dcd66a549, LangChain4j 1.21.0, Script Editor 1.4.3. Future upstream builds require compatibility checks. Private logs, images, credentials and dependency JARs are not bundled.
