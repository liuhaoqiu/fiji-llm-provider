# Fiji LLM Provider 0.6.0

[English](v0.6.0.md) | **简体中文**

本版让每次对话有一个自己的输出文件夹，并消除实际任务中暴露出的两类“无提示”的问题：一个宏参数在没有任何提示的情况下关掉了 GPU；过大的工具结果跟着之后的每一次请求反复发送。和以往一样，每项修改都来自实际 Fiji Chat 任务中观察到的问题，没有一项增加分析方法。

## 每次对话一个输出文件夹

此前每次对话都由模型自己决定文件放在哪里、叫什么名字。现在，会产生文件的对话在输入图像所在目录下得到一个自己的文件夹：

```text
Fiji_chat_output_<yyyymmdd>_<n>/
  report.md          聊天窗口中显示的最终报告（后续的回答：report_2.md）
  results/           二维标签分析的标准结果（第二套：results_2/）
  scripts/           用 fiji_script_save_file 保存的脚本
  script_output/     要求对话中的脚本把自己产生的文件写到这里
  process/           对话中实际运行过的每个脚本（按运行顺序编号）和 steps.md
  manifest.json      每个文件的大小和哈希、输入图像、所用助手
```

编号按该目录下当天的文件夹递增，由扩展通过“创建文件夹”来分配，所以两次对话不可能共用一个，已有的文件夹也不会被复用。新增工具 `fiji_output_folder` 返回该文件夹；`fiji_script_save_file` 和 `fiji_analysis_save_bundle` 默认使用它。

**标准结果**包含标签 TIFF、固定列的测量表、每个标签一条 ROI、质控图和脚本快照。原图如果是磁盘上未改动的文件，就以路径和像素哈希标识，不再复制；其他情况（例如只存在于内存中的灰度副本）则作为 `source.tif` 随结果一起保存。固定格式适用于二维标签分析；其他类型的任务仍有文件夹、报告、脚本、过程记录和清单，结果文件由模型命名。

**不约束宏的行为。** 脚本可以写到任何被要求的位置，交付的宏常常写到图像旁边它自己的文件夹里。清单会在 `new_files_next_to_the_input` 中列出这些文件（最多向下三层）。如果保存的脚本里以字面路径写着本次对话的文件夹，保存结果和清单会注明，因为这样的脚本以后复用时会写回旧文件夹。

**交付的宏不依赖本扩展。** 此前工作流提示会引导模型使用 `fiji_command_macro_template`，而它生成的宏会调用本扩展，在没有安装本扩展的 Fiji 中无法运行。现在要求模型编写普通的宏代码。该工具仍然保留，供明确需要的人使用，其说明里写明了生成的宏依赖什么。

**不会发生的事。** 没有运行脚本也没有保存文件的对话不会创建文件夹。图像从未保存到磁盘或其所在目录不可写时不会创建文件夹，记录留在本地归档。扩展写入的文件不会替换已有文件。报告、步骤或清单写入失败不会影响分析。此功能可在 **LLM Execution Settings** 中关闭。

## 宏里写成 1 的布尔参数

宏变量设为 `true` 后拼进字符串会变成 `1`，而 SciJava 把选项文本 `1` 读成“否”，且没有任何提示。于是 `run("Cellpose...", "... usegpu=" + useGPU)` 实际跑在 CPU 上。这在两次实际任务中出现过；其中一次没有人发现，它的摘要里还写着 GPU 已开启。

- `fiji_command_parameters` 的说明现在写明：布尔参数必须写成文字 `true` 或 `false`。
- 对话启动的宏在调用命令时，如果传入了既不是 `true` 也不是 `false` 的布尔参数，`fiji_macro_run` 或 `fiji_macro_run_status` 的结果里会带上 `macro_option_warnings`，指出是哪个命令的哪个参数，聊天窗口也会显示这一行。

第二点只是观察。它是一个 SciJava 预处理器，读取的是 ImageJ 自己的宏预处理器读取的同一段选项文本，不修改任何输入和结果；无论在对话里还是对话外，宏的行为都与没有安装本扩展时完全一样。

## 更小的工具结果

**超大工具结果里的长列表。** 列出全部 ROI 或全部表格行的工具，在对象有几千个时会返回几十万字符，而对话记忆会在之后的每次请求中把它们再发送一遍。一次实际任务中，52 万和 55 万字符的两份 ROI 列表跟着一百多次请求一起发送。现在，超过 3 万字符的工具结果在请求发出前，会把其中最长的 JSON 列表缩短为前 20 行，直到大小合适为止。被缩短的列表末尾注明省略的行数和总行数；结果里说明它被缩短过以及完整结果在哪里；其他字段保持不变。文字内容从不截断，脚本和日志完整送达；低于门槛的结果完全不受影响。完整结果仍保存在本地归档中，步骤记录里会记下每次缩短。此功能可在 **LLM Execution Settings** 中关闭。

**`fiji_analysis_save_bundle` 的返回结果。** 此前结果里会重复“标签—ROI”对照表，4300 个细胞约 19 万字符。现在超过 20 行的对照表只给出一行示例和总行数，完整对照表仍在该结果集的 `manifest.json` 中。

## 范围

与 0.5.23 相比，JAR 中下列类、SciJava 插件索引和版本清单有变化：`AnalysisBundle`、`AssistantExecutionSettings`、`BoundedContext`、`ConfigureAssistantExecution`、`ProgressAssistant`、`ProviderAssistantService`、`StagePresentation`、`StageReporting`、`UiAutomationTools`、`WorkflowTools`，以及新增的 `ChatOutput`、`LongLists` 和 `MacroOptionCheck`。Fiji Chat 和 Script Editor 的原始 JAR 没有被修改。

## 安装或升级

1. 先安装 Fiji Chat。保存工作并关闭 Fiji。
2. 从本次发布下载 **fiji-llm-provider-0.6.0.jar**，可用 **SHA256SUMS.txt** 校验。
3. 把 JAR 复制到 Fiji 的 **jars/** 目录。停用旧版本的扩展 JAR，只保留一个版本生效。保留 Fiji Chat 和 Script Editor 的原始 JAR。
4. 重新启动 Fiji。通过 **Help → Assistants → Manage API Keys...** 管理密钥；通过 **Help → Assistants → Refresh LLM Models...** 刷新模型，然后重新打开模型选择器。

源码 ZIP 用于查看和构建，不用于安装。

## 验证与局限

**27 组回归在一次构建中全部通过**，对应下面列出的 Fiji Chat 构建；新增的一组覆盖输出文件夹。新增的检查覆盖上述每一项修改：通过创建文件夹来分配编号；报告、脚本、步骤和清单的写入不替换任何已有文件；标准结果只在原图不是磁盘文件时复制原图；脚本在输入旁新建的文件夹中的文件；字面路径提醒；功能关闭、图像未存盘、目录不可写以及写入失败时分析不受影响；布尔参数提醒以及参数正确时保持沉默；长列表缩短并注明行数，而文字、较小的结果和关闭开关时结果保持完整。

六组原生 GUI 测试在发布构建上运行过，另外从宏里真实调用了两次已安装的 Cellpose 命令：一次用 `usegpu=1`，命令照常运行并被报告；一次用 `usegpu=true`。

开发期间用 DeepSeek 在同一张图像上、在本版本的各次构建上运行了五次真实任务，实际用到了输出文件夹、报告和步骤记录、包含“宏留在图像旁的文件”的清单、带原图副本和不带原图副本的标准结果、缩小后的结果返回，以及在最长六分钟的运行上的有界状态等待。

未验证的部分：

- 长列表缩短加入之后，没有在真实任务中发生过；它用三条真实任务的归档结果（552,848、519,790 和 59,247 字符）测试过，另有一条归档的 22,098 字符的界面控件列表会被完整发送。
- 布尔参数提醒没有在真实任务中发生过，因为参数工具写明写法之后，模型都写对了。
- **LLM Execution Settings** 中新增的两个复选框没有在屏幕上检查过，README 中的截图是本版之前的对话框。
- 真实任务中请求了 GPU；Cellpose 命令本身不回报实际使用的设备。
- 这些检查都不涉及科学准确性。五次真实任务中，模型对同一张图像报告的细胞数分别是 4304、4306、4296、4296 和 4306，并且每一次都有密集细胞团未被完全分割。

测试环境：Windows 11、Java 21.0.13.1、Fiji/ImageJ 2.18.0 / 1.54p、Fiji Chat 0.2.0-SNAPSHOT（提交 1dea483ee7285efb86689902b4cae56dcd66a549）、LangChain4j 1.21.0、Script Editor 1.4.3。未来上游构建仍需兼容性检查。不包含私有日志、图像、密钥或依赖 JAR。
