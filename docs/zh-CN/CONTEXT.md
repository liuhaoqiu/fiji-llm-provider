# 上下文预算与阶段进度恢复

[English](../CONTEXT.md) | **简体中文**

在 **Help > Assistants > LLM Execution Settings...** 中设置上下文预算。
默认工具调用上限仍为 1000 轮。保存后重新打开 Fiji Chat。

## 设置窗口与请求体大小

- **Context window tokens = 0**：自动读取模型目录的上下文窗口；缺少元数据时
  回退到 32,768 token。手动设置也不会超过已知模型窗口，无法借此扩大服务端能力。
- **524288** 对应 512K 窗口，**1048576** 对应 1M 窗口。
- **Reserved output tokens**：默认预留 65,536 token，受模型输出上限及窗口四分之一
  的限制。输入预算是总窗口减去输出预留。实际请求的输出上限也会相应限制；原有更小
  的输出设置继续保留。
- **Maximum request body MiB = 0**：DeepSeek 官方 API 使用 48 MiB；其余三个服务商
  使用可调整的本地回退值 16 MiB。这不代表其他服务商的实际服务端上限。
  正数可覆盖本地限制。1 MiB = 1,048,576 字节。

DeepSeek 模型目录目前报告 1,048,576 token 窗口，其[视觉文档](https://api-docs.deepseek.com/guides/vision/)
另外规定请求体上限为 48 MiB，内嵌 Base64 图像也计入。两项限制需要分别管理。

## 查看运行中的上下文

打开 **Help > Assistants > LLM Context Status...**。窗口每秒刷新，显示最近活跃助手的
估算输入 token、有效输入预算、实际序列化请求字节数，以及上一次完整 API 响应返回的
实际输入 token（服务商提供时）。

token 估算采用本地 gpt-4o 分词器近似计算；DeepSeek 图像采用其当前文档的每图
1024 token 上界，其他服务商保留较保守的图像估算。不透明推理数据也作保守估算。
无法在服务端处理前精确获知下一次实际输入 token。API usage 对应上次完整请求；
UTF-8 JSON 字节数则是在发送前实测。监测窗口不会记录 API 请求头或密钥。

## 自动整理与阶段输出

接近输入预算 80% 或请求体限制 90% 时，插件先归档原始消息，再缩小工作上下文：
保留系统指令、当前任务及最近的完整工具调用批次，把较早活动整理为有长度限制的
**提取式摘录**，并提供完整消息文件位置。过大的文本工具结果也可变为明确标记的摘录；
最近的图像和最新的不透明推理数据不会被静默改写。工具调用 ID 与结果保持配对。

替换工作记忆前会保存阶段检查点，详细检查点进入持续更新的运行日志；回答区仅显示简短的阶段结果摘录，避免长摘要把运行日志挤出视野。提示限频，避免刷屏。
这些摘录不代表已经独立验证任务成功，助手仍需检查当前脚本、图像和确切结果。

如果仍然触发上下文或请求体超限，会在聊天中输出 **任务暂停 / Task paused — not completed**，
保留任务、近期活动和归档位置，避免走原版失败回滚流程。可在同一对话输入 **继续**；
下一次请求采用更紧的预算。该机制不会自动重放已经完成的工具操作。
若单个任务、图像或最新工具批次本身无法安全容纳，则保留检查点并继续暂停。
连接中断的处理见下文；其他类型的错误沿用正常错误处理。

## 完整记录保存在本地

目录为 `%LOCALAPPDATA%/FijiChat/context-archives/<session-id>/`；没有 LOCALAPPDATA 时
使用 `~/.cache/FijiChat/context-archives/`。

- `message-*.json`：完整消息，包含图像数据、推理属性。
- `index.txt`：消息添加顺序。
- `stream-events.jsonl`：已收到的文本和思考进度回调，包含失败流的未完成输出。
- `checkpoint-*.md`：历次阶段记录；`checkpoint.md` 为最新版本。

本地归档独立于模型工作记忆，可能包含私人图像或脚本，不会作为发行附件上传。
清空聊天记忆不会自动删除这些归档；长期使用可能占用较多磁盘空间。
归档写入失败会停止处理，不会假称已完整保存。这是同一对话内的上下文恢复，
不代表重启 Fiji 后能够自动恢复宏、图像或外部进程的执行状态。

## 验证范围

本地测试覆盖 UTF-8 字节边界、四个服务商 HTTP 构建器、同步/SSE 请求、真实助手循环、
完整图像归档、大型工具结果自动整理、原版 Fiji 聊天面板和活动保存，以及不重复执行
已完成工具的同对话续接。测试不使用真实 API 密钥。
实际复杂显微图像任务仍需手动集成验证，不能把本地测试等同于该工作流已验证成功。

## 等待状态与连接中断（0.5.5）

连续 60 秒未收到新的模型输出或工具事件时，插件会在运行日志中显示明确标注的状态，
最多每分钟一次：区分“等待 API 新输出”和“等待工具返回”，显示等待时长及最后完成的工具。
连接仍在或计时仍在增长，不代表任务在推进。首次提示还会在回答区增加一条简短说明。
这些是插件观测到的状态，不是模型思考，也不是科学结果或完成报告。

**Help > Assistants > LLM Context Status...** 同时显示当前活动状态和距最近输出/工具事件的秒数。
尚未形成完整工具调用的参数片段也计为模型活动。

原有 30 分钟超时现在也能约束收到 HTTP 响应头之后的 SSE 正文空闲读取。
收到数据事件会重新计时，只有保活注释不会；同步工具回调长时间执行不会触发网络空闲超时。
这是单次请求的空闲上限，不是整个任务只能运行 30 分钟。

识别到连接超时、中断或空的最终回复时，插件会保存并显示“任务暂停、尚未完成”的阶段记录，
保留已经显示的活动，便于在同一对话中输入“继续”。不会自动重试请求或重放工具。
中断的请求可能已经到达服务商。新增流式归档事件带 UTC 时间戳。
插件不能强迫上游服务产生答案，真实服务商行为仍需集成验证。

## 任务保留与模型元数据（0.5.5）

新对话有独立记忆和归档目录。新窗口的请求仍包含工具定义、环境信息及图像，并非只计算输入框中的文字。
1M token 窗口与 HTTP 请求体字节预算是两项限制；单张图像经 PNG/Base64 编码就可能占很多 MiB。

硅基流动 API 未提供上下文长度时，插件从[硅基流动官方模型页](https://www.siliconflow.cn/models)
的结构化数据补充该字段。模型选择列表仍以 API 返回的 ID 为准，不从网页增加模型。
元数据最长缓存 24 小时；**Help > Assistants > Refresh LLM Models...** 会强制刷新两项来源。
官网元数据请求限时 5 秒，不发送 API 密钥或对话内容。失败时保留最后有效缓存；两处均缺少长度时，
仍使用保守的 32,768 token 回退值，并在 **LLM Context Status...** 明确显示来源、总窗口与输出预留。
手动窗口设置继续生效，也继续受已知模型上限约束。

初始用户任务及最近最多三条追问独立保留。每次请求都会恢复缺失的任务，即使请求未达到压缩阈值。
用户改变任务时，以最新指令为准。自动摘要不会成为新的用户任务；不同对话之间不共享任务或归档。
若任务本身无法容纳，则明确暂停，而不是静默删除目标。

Chat Completions 协议中被移动到 user 角色的工具图像会明确标为“当前任务的工具证据”，
避免将它理解成新的空用户请求。整理提示区分 token 压力和请求体字节压力；字节软阈值调整为 90%，
为实际传输编码保留余量。上述机制保证任务内容保留，不保证托管模型每次都正确遵循；科学结果仍需核对。
