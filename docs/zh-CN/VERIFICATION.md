# 0.6.0 验证

[English](../VERIFICATION.md) | **简体中文**

**27 组回归在一次构建中全部通过。** 新增的一组覆盖输出文件夹。新增的检查覆盖 0.5.23 之后的每一项修改：通过创建文件夹来分配编号；报告、脚本、步骤和清单的写入不替换任何已有文件；标准结果只在原图不是磁盘文件时复制原图；脚本在输入旁新建的文件夹中的文件；字面路径提醒；功能关闭、图像未存盘、目录不可写以及写入失败时分析不受影响；宏里写成 1 的布尔参数的提醒，以及参数正确时保持沉默；超大工具结果里的长列表缩短并注明行数，而文字、较小的结果和关闭开关时结果保持完整。

六组原生 GUI 测试在发布构建上运行过，另外从宏里真实调用了两次已安装的 Cellpose 命令：一次用 `usegpu=1`，命令照常运行并被报告；一次用 `usegpu=true`。

开发期间用 DeepSeek 在同一张图像上、在本版本的各次构建上运行了五次真实任务，实际用到了输出文件夹、报告和步骤记录、包含“宏留在图像旁的文件”的清单、带原图副本和不带原图副本的标准结果、缩小后的结果返回，以及在最长六分钟的运行上的有界状态等待。

**未验证的部分。** 长列表缩短加入之后，没有在真实任务中发生过；它用三条真实任务的归档结果（552,848、519,790 和 59,247 字符）测试过，另有一条归档的 22,098 字符的界面控件列表会被完整发送。布尔参数提醒没有在真实任务中发生过，因为参数工具写明写法之后，模型都写对了。LLM Execution Settings 中新增的两个复选框没有在屏幕上检查过。真实任务中请求了 GPU；Cellpose 命令本身不回报实际使用的设备。这些检查都不涉及科学准确性：五次真实任务中，模型对同一张图像报告的细胞数分别是 4304、4306、4296、4296 和 4306，并且每一次都有密集细胞团未被完全分割。

自动化测试使用合成模型、合成工具和本地服务，不使用 API 密钥、在线推理或用户图像。

环境：Windows 11、Java 21.0.13.1、Fiji/ImageJ 2.18.0 / 1.54p、Fiji Chat 0.2.0-SNAPSHOT（提交 1dea483ee7285efb86689902b4cae56dcd66a549）、LangChain4j 1.21.0、Script Editor 1.4.3。未来上游构建仍需兼容性检查。不包含私有日志/图像、密钥或依赖 JAR。
