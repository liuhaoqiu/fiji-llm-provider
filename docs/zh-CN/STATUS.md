# 执行状态与编辑器兼容（0.5.13）

[English](../STATUS.md) | **简体中文**

本地更新改善四家扩展服务商的错误与状态显示；不增加科学方法选择、专用 QC 策略、工具审批或自动重试，保留默认上限和服务商设置。

## 未知工具名（0.5.19）

未知/畸形名称返回 `unknown_tool` / `executed: false`，供模型自行纠正；不猜测或修复名称，不重放已完成操作，仍受原有有限轮数约束。扩展外服务商保留原服务。详见[发布说明](../releases/v0.5.19.zh-CN.md)。

## 已保存脚本核验条（0.5.18）

最终报告使用最近成功导出的脚本快照。后续清理、编辑或标签重命名不改变保存时的身份，失败导出不替换成功快照。核验条明确指向保存的代码，不代表编辑器当前内容；未导出时保留原行为。详见[发布说明](../releases/v0.5.18.zh-CN.md)。

## 忙碌与启动失败

冲突启动返回 `status: busy`、`started: false`、请求脚本 ID，以及已知的占用脚本名称/ID。Fiji Chat 已返回运行 ID 时，附 `blocking_run_id` 与对应状态查询工具；初始启动期间、或由外部操作启动的编辑器任务，不编造未知运行 ID。原任务不会被取消或重放。真正启动失败时，在运行日志保留异常原因链，并在正文提供限长原因摘要。

## 脚本版本核验范围

精确字节核验目前记录本扩展的宏执行。普通脚本继续使用 Fiji Chat 原执行服务；核验器返回 `not_monitored` 和 `execution_evidence_supported: false`，明确表示未覆盖该语言，不能解释成脚本未运行或运行失败。输出和结束状态以其执行回执为准。宏编辑后仍会使旧哈希匹配失效；两类记录均不证明空白状态复现或科学正确性。

## Script Editor 1.4.3 兼容处理

原编辑器在运行收尾时查找当前选中标签的错误高亮器。真实 Groovy 隔离复现表明，运行期间创建并切换到新标签，会在正文结束后从 `ErrorParser.parse` 抛出 `Writer is null`。现在 `fiji_script_create` 遇到最近编辑器仍有任务时，会在另一个编辑器窗口创建新脚本，保留原窗口的活动标签，并返回 `editor_placement: separate_window_existing_editor_running`。

该处理避免了本次插件创建标签引发的路径，不修改原编辑器 JAR，也不替换普通脚本引擎。手动切换标签、其他编辑器 API 仍由上游处理，不能声称已修复所有错误高亮竞争。真实脚本错误与部分输出继续保留。

## API 等待与展示异常（0.5.17）

活动监测使用工具开始/结束元数据和 API 活动。本地 0.5.13 的实验性后台回执解析在 0.5.15 已撤销，不属于当前功能。非关键状态/展示异常与工具结果交付隔离，原始载荷与真实执行错误保留。

正文区分普通输入弹窗和明确含 error_dialog 文本的错误弹窗；限长原因作为行内代码展示，保留尖括号定位标记。详见 [0.5.17 说明](../releases/v0.5.17.zh-CN.md)。
