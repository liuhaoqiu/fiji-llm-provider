# 宏执行兼容（0.5.7）

[English](../MACRO-EXECUTION.md) | **简体中文**

Cellpose 可能很快完成，但 Fiji Chat 长时间把宏报告为 `running`。
已复现的情况是：脚本求值已返回，编辑器仍在收尾阶段等待关联线程。
增加轮数、上下文容量或继续轮询，无法解除这个等待。

插件新增优先级更高的 `.ijm` 宏执行兼容服务。它读取当前可见编辑器中的宏，
沿用 SciJava 模块及参数处理流程，通过独立求值范围区分宏任务和编辑器/控制台维护。
宏求值及其创建的真实子线程都会等待，包括正在休眠的子线程；不按线程名字猜测，
也不强制结束线程。其他脚本语言交给 Fiji Chat 原执行服务。

0.5.6 仍可能在大图处理后永久等待：JVM 公共线程池的工作线程会继承首次提交任务的线程组，
但空闲后仍长期存活。0.5.7 仅排除真实公共线程池中停在空闲等待栈的线程；
仍在计算的工作线程、普通休眠子线程和私有线程池继续等待，也不受公共池中无关任务的牵连。
若仍有待结束的子线程，工具状态会增加 `pending_child_threads` 诊断。
ImageJ 堆栈窗口同样会创建继承线程组的层选择器事件循环；插件排除
`ij.gui.StackWindow.run` 中的空闲 `Object.wait`，仍等待正在更新的选择器。
两类识别均不依赖线程名字，也不结束线程。

保留 run_id、首次等待上限、状态查询、控制台/ImageJ 日志、环境变化及对话框/错误报告。
超过 30 秒仍在运行时返回 `running` 与 `wait_expired`，不会取消或重新执行宏。
输入窗口保持阻塞状态；关闭宏错误窗口后仍报告失败。工具结果会显示
`execution_backend: Fiji LLM Provider macro module`。
该路径应以工具返回的状态为准，不依赖编辑器原有的 Running 标题。
兼容服务用于 Fiji Chat 共用的宏工具，适用于不同 LLM 服务商。

只需安装新版扩展 JAR 并重启 Fiji，保留原版 Fiji Chat 和 Script Editor JAR。
已卡住的旧调用不会原地修复；重启前先保存宏、标签图、ROI 和结果表。

执行成功不代表分割准确。若宏显式启动求值范围外的独立任务，需要查询该任务自己的状态。
范围内不明的常驻子线程仍保留运行状态，插件不会猜测并强杀。停止聊天也不会撤销已完成的操作。

## 验证

十五组本地测试通过。冷启动测试复现 0.5.6 的等待，并覆盖共享线程改名、真实计算、无关任务及私有池。
另在独立 GUI/模块进程中验证了真实堆栈窗口的选择器与正常关闭、连续运行、31 秒真实等待、防重复启动、
输入与错误窗口以及原服务委托。在 128×128 合成图上实际调用 Cellpose，新版包含进程启动
约 10.5 秒后返回 `success`；原版同样已经打印完成标记，却在首次等待 30 秒后仍返回 `running`。

大图验证另对 3000×3000 RGB 实际调用 Cellpose，导出 ROI、写入计数表并继续执行下一条宏。
除合成图外，使用了本次任务的本地图像预览副本，未上传或随包分发。
使用已安装的 Cellpose-Appose 0.1.24 和 nuclei 模型，不使用托管推理 API。
验证的是执行行为，不是生物学分割准确率。具体结果详见[发行验证](VERIFICATION.md)。

默认构建运行本地测试。Windows 桌面及依赖齐全时，可加 `-VerifyMacroIntegration` 做 GUI/模块验证；
加 `-VerifyCellpose` 做实际 Cellpose 验证。后者需要 Cellpose 插件、环境和模型，缺失时可能下载组件。
可同时指定 `-CellposeFixture "C:\path\to\RGB-image.png"`，用自己的本地图像验证非空 ROI 导出。
